From a UF2 file to a running watch

How can firmware update while it is running?

The key is to move the small flashing program from flash into RAM. It can then erase the application that contained it, receive the remaining blocks over infrared, and reboot only after verifying the complete image.

In one line: PC → USB/IR modem → watch receiver → flasher in RAM → application flash → final CRC → reboot.

In the observed session, the heap extended to 0x20004000, leaving 4096 B before the overlay. UltraPatch required 6716 + 512 = 7228 B to allocate its state. The allocation failed for lack of space, so the first frame received no ACK.

A full flash uses the 7664 B overlay without allocating PatchApply. The 4096 B of free space reflect the observed session; they do not limit a full image transfer.

After copying the first frame and leaving Movement, UltraPatch reuses the heap from 0x20002DBC to 0x200047F8. Its 6716 B end 2056 B before the overlay. A full flash uses the same overlay without allocating this state.

After rebooting, the new firmware rearranges RAM. This map shows the measured update session, not memory use after startup.

Addresses and sizes come from the measured sensorwatch_pro build. The overlay loads when the first block arrives; the linker requires it to end before 0x20007600 to leave room for the stack.

256 B

One flash row

In full-image mode, each block carries a 4-byte address and 256 data bytes. A row is erased and programmed as four 64-byte pages.

ACK

Stop and wait

The watch returns the 2-byte ID only after processing a block. If the ACK is lost, the PC resends it; the watch recognizes the duplicate and replies without writing twice.

CRC‑32

Boot gate

Each frame has its own CRC. At the end, the watch calculates another CRC over the entire written image and reboots only if it matches the expected value.

How can it erase its own firmware?

BeforeThe Movement face and the overlay's load copy reside in flash. The face checks the link and prepares the first block.
HandoffIt copies the overlay into RAM, verifies the copy, disables interrupts, and hands control to flasher_run.
PatchThe flasher copies the first frame into its buffer. Only then can the decoder overwrite the heap used by Movement. A full flash does not need this extra state.
DuringThe core and decoder run from RAM while the NVM controller erases and programs application flash rows.
AfterSuccessful verification triggers a reset. The UF2 bootloader starts the new firmware; the temporary overlay disappears from RAM.

If the session is interrupted

No ACKThe host retries the same frame. A repeated ID for the last block receives an ACK without another write.
Bad CRCThe watch does not ACK EXIT and stays in the RAM loop. It can receive another full image starting at block 0.
PatchPatch ENTER checks the base image's CRC before writing. Because the patch modifies the base in place, recovery from a failure requires sending the full image.
LimitBy default, the host requires the new image to retain the flasher face; without it, another IR update would be impossible. The user can explicitly override this safeguard.
